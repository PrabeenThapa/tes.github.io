Control Memory & Microprogrammed Control

The book starts with control memory (also called the control store): a special memory inside a microprogrammed control unit that stores the microprogram used to generate CPU control signals.

Core idea

A normal program tells the CPU what instruction to perform. A microprogram tells the control unit which tiny internal operations (microoperations) are needed to make that instruction happen.

Control memory, microinstruction, and microprogram

  • Control memory: stores control information for the CPU. The source describes it mainly as ROM, although it also mentions writable control memory for dynamic microprogramming.
  • Microinstruction: one word in control memory. It contains control bits that initiate microoperations and bits that help determine the next control-memory address.
  • Microprogram: a sequence of microinstructions that implements a machine instruction or control routine.
Machine instruction→Control unit→Microprogram→Microoperations→CPU datapath action

Why separate control memory from main memory?

The source treats the microprogram as control information separate from ordinary instructions/data. The control unit can read the control store quickly and produce the internal signals that move data between registers, memory, and the ALU.

Two memories in a microprogrammed computer

Main memory

Stores program instructions and ordinary data.

Control memory

Stores the microprogram used by the control unit.

The source also introduces two important control-store registers:

  • Control Address Register (CAR): specifies the address of the microinstruction to read.
  • Control Data Register: holds the microinstruction read from control memory.

Hardwired vs microprogrammed control

Hardwired controlMicroprogrammed control
Control signals are produced by logic circuits.Control signals are described by microinstructions in control memory.
Generally faster but harder to modify.More systematic/flexible and easier to change.

Memory ideas introduced by the book MCQs

  • RAM: working memory for data/programs currently being used.
  • ROM: non-volatile memory; the MCQs associate BIOS storage with ROM.
  • Cache: small, fast memory for frequently used instructions/data.
  • Virtual memory: extends the apparent memory space; address translation is associated with the MMU.
  • Memory controller: regulates data flow between CPU and memory.
  • MMU: maps virtual addresses to physical addresses.
Exam focus
  • Control store = control memory.
  • One control-memory word = microinstruction.
  • A sequence of microinstructions = microprogram.
  • CAR chooses the next control-memory location.
  • Cache is smaller/faster than main memory and normally volatile.

Address Sequencing, Branching & Mapping

A microprogram is useful only if the control unit knows which microinstruction comes next. Address sequencing is the logic that chooses that next control-memory address.

Typical sequence after power-on

  1. An initial address is loaded into the control address register.
  2. The first microinstruction normally starts the instruction-fetch routine.
  3. The control unit may enter a routine that determines the effective address of the operand.
  4. It then executes the microoperations that implement the fetched instruction.

Four ways the next control address can be obtained

1. Increment

CAR ← CAR + 1, so execution falls through to the next microinstruction.

2. Branch

Load a different control-memory address, either unconditionally or depending on a status bit.

3. Mapping

Convert bits from the machine instruction (especially opcode bits) into the starting address of a microprogram routine.

4. Subroutine call/return

Jump to a reusable control routine and later return via a saved address.

Conditional branching

The branch logic can examine status information such as overflow (O), negative (N), zero (Z), and carry (C). A multiplexer selects a status bit; the branch field and selected condition then determine whether CAR receives a branch address or simply increments.

Conceptual ruleif condition = 1 → CAR ← branch address
else → CAR ← CAR + 1

Mapping instruction opcode to a microprogram

The source gives a simple mapping example that converts a 4-bit opcode to a 7-bit control-memory address by placing:

  • 0 in the most significant bit,
  • the four opcode bits next,
  • 00 in the two least significant positions.
Example from the source patternopcode 1011 → 0 1011 00 → microinstruction address 0101100

This reserves four consecutive control-memory words for each opcode routine.

Subroutine register (SBR)

The sequencing hardware includes an SBR so a microprogram can call a subroutine, save its return address, execute the subroutine, and then return.

Exam focus
  • Address sequencer = next-address decision logic for control memory.
  • Status bits enable conditional microprogram branches.
  • Mapping connects machine-instruction opcode patterns to microprogram start addresses.
  • Subroutine call/return requires saving a return address, typically in SBR.

Two memory units

  • Control memory: stores the microprogram.

The figure labels main memory as 2048 × 16, with DR and AC shown as 16-bit registers. CAR and SBR belong to the control unit.

Control-unit registers

  • CAR: control address register, used to select a microinstruction.
  • SBR: subroutine register, used to save the return address during microprogram subroutines.

Why multiplexers appear in the configuration

The source states that information transfer among processor registers is done through multiplexers rather than a common bus in this configuration. A multiplexer chooses one of several possible data sources and sends the selected source onward.

Control Unit Design & Microprogram Sequencer

The source shows how encoded microinstruction fields are turned into real hardware control signals, then how a microprogram sequencer chooses the next control-memory address.

Why encode fields?

Instead of giving every possible control signal its own bit, mutually exclusive microoperations can be grouped into fields. If a field has k bits, it can encode up to 2k choices.

Benefit

Fewer bits are needed in each microinstruction, making control memory narrower.

Cost

A decoder is required for each field; this adds hardware and propagation delay.

Decoding F1/F2/F3

The diagram uses three 3×8 decoders. Each decoder activates one output based on its 3-bit field. Those outputs become signals such as ADD, AND, register-load controls, or transfers into AR/AC.

Microprogram sequencer

The sequencer's purpose is to present an address to control memory so the next microinstruction can be read and executed.

  • A first multiplexer selects one of several candidate addresses for CAR.
  • A second multiplexer selects a status bit to test.
  • CAR supplies the current control-memory address.
  • An incrementer generates CAR+1.
  • SBR holds the return address for a microprogram subroutine.
  • CD and BR bits feed input logic that decides which sequencing operation to perform.

Typical sequencer operations

IncrementBranch / jumpCallReturnLoad external/mapped addressStack operations

Hardwired, microprogrammed, hybrid, state-machine ideas

The MCQs on printed page 342 review multiple implementation styles. Hardwired control produces control signals using gates/flip-flops, while microprogrammed control uses a control program stored in ROM/control memory. State-machine control is implemented with sequential logic.

Exam focus
  • Encoding reduces microinstruction width but requires decoders.
  • Sequencer = next microinstruction address generator.
  • CAR = current control address; SBR = microprogram return address.
  • Hardwired control uses logic; microprogrammed control uses a stored control program.

CPU Structure, Registers & Fetch–Decode–Execute

The source divides a typical CPU into the Control Unit, Arithmetic Logic Unit (ALU), and Registers.

Control Unit

Fetches and decodes instructions and sends control signals to the rest of the CPU. Think of it as the coordinator: it decides what must happen next.

ALU

Performs arithmetic and logical operations. It receives data from registers and executes the operation requested by the control unit.

Registers

RegisterWhat to remember
PCAddress of the next instruction to be executed/fetched.
IRCurrent instruction being executed.
MAR / address registerMemory address of data/instruction being accessed.
AccumulatorIntermediate/final arithmetic or logic results.

Fetch–decode–execute cycle

1. Fetch
Get instruction from memory→2. Decode
Control unit interprets it→3. Execute
ALU/datapath performs operation→Store/update state

The cycle then repeats for the next instruction indicated by PC.

System bus and CPU performance

The CPU exchanges data/control information with memory and I/O devices through the system bus. The source emphasizes clock speed and also notes that core count, cache size, and instruction-set architecture affect performance.

Von Neumann idea in the MCQs

The exact book questions identify a single shared path/bus for instructions and data as the Von Neumann-style choice, contrasting it with separated instruction/data paths.

Exam focus
  • PC = next-instruction address; IR = current instruction.
  • Correct order: fetch → decode → execute.
  • Control unit coordinates; ALU computes.
  • Clock speed is a frequency, commonly expressed in GHz for modern CPUs.

Arithmetic & Logic Unit (ALU)

The ALU takes input values, performs the operation selected by the control unit, and produces a result. The source groups ALU work into arithmetic, logic, bit manipulation, and status/overflow handling.

Arithmetic operations

Addition, subtraction, multiplication, and division are listed. Addition/subtraction are basic building blocks; multiplication/division may require sequences of simpler operations.

Logic operations

ABANDORXOR

01011
10011
11110

NOT flips a single bit: 0→1 and 1→0.

Shift vs rotate

Shift

Moves bits left or right; bits shifted out are normally discarded and new bit positions are filled according to the shift type.

Rotate

Moves bits left/right but wraps the bit leaving one end around to the other end.

Flags

The source prose explicitly discusses an overflow flag; the MCQs also test zero, carry, and negative flags. Flags summarize properties of the result and can influence later control decisions.

  • Zero flag: result is zero.
  • Carry flag: carry/borrow-related unsigned condition.
  • Negative/sign flag: sign information.
  • Overflow flag: result cannot be represented correctly in the available signed range.

Accumulator and throughput

The accumulator is a register used to store ALU results and intermediate values. The source describes ALU performance in terms of throughput—how many operations can be completed per unit time.

Important source-quality warning

Several ALU MCQs on printed page 346 conflict with the theory printed on page 345 or contain more than one true option. The practice app deliberately scores using the book's printed answer key but displays an inconsistency warning after you check such questions.

Exam focus
  • ALU = arithmetic + logic + bit manipulation.
  • AND needs both 1; OR needs at least one 1; XOR needs different inputs.
  • NOT inverts.
  • Shift and rotate are not the same.
  • Accumulator stores ALU results.

Instruction Formats

An instruction format defines how the bits of an instruction are divided so the CPU can identify the operation and its operands.

Formats described in the source prose

Format ideaWhat it meansExample style from source
RegisterOperands are registers.ADD R1, R2
ImmediateAn immediate constant is encoded in the instruction.ADDI R1, 5
MemoryInstruction accesses a memory location.LOAD R1, 100
BranchChanges the instruction-flow location.BRANCH 200
Floating-pointUses floating-point registers/operations.ADDF F1, F2

Zero-, one-, two-, and three-address formats

The MCQs introduce another classification based on how many explicit operand addresses are present:

  • Zero-address: no explicit operand addresses; operands are implied (commonly stack-oriented conceptually).
  • One-address: one explicit operand address; another operand may be implied.
  • Two-address: two explicit operand fields.
  • Three-address: three explicit operand fields; generally uses the most instruction space.

R-, I-, and J-type questions

The book's MCQs also test MIPS-style R, I, and J formats. Because a few of these items/keys are technically questionable, the app preserves the printed question and printed answer exactly and flags the questionable ones rather than silently rewriting them.

Exam focus
  • Instruction format tells the decoder where opcode/operand fields are.
  • More explicit addresses usually means a longer instruction.
  • Immediate = constant encoded with the instruction.
  • R-type is associated with register arithmetic/logic; J-type with jumps; the book associates I-type with memory loads.

Addressing Modes

An addressing mode tells the CPU where the operand is or how to calculate its effective address (EA). This is a frequent exam topic because similar modes are easy to confuse.

ModeSimple meaningSource-style example
ImmediateThe value itself is inside the instruction.MOV R1, #5
RegisterThe operand is in a register.ADD R1, R2
DirectThe instruction directly gives the memory address.MOV R1, [100]
Indirect / register-indirectA register contains the address of the operand.MOV R1, [R2]
IndexedAddress is formed from a register plus an offset/index.MOV R1, [R2 + 4]
RelativeAddress is formed from PC plus an offset.JMP $+10
BaseAddress is formed from a base register plus an offset.MOV R1, [R2, #4]

Effective-address shortcuts

Immediate: operand = constant
Direct: EA = address field
Register-indirect: EA = contents of address register
Indexed/Base: EA = register + offset
Relative: EA = PC + offset

How to avoid common confusion

  • If the instruction contains the value → immediate.
  • If the instruction contains the actual memory address → direct.
  • If a register contains the memory address → indirect/register-indirect.
  • If you add a register and offset → indexed/base.
  • If the offset is added to PC → relative.
Exam focus
  • Arrays → indexed addressing is a common association in the book.
  • Relative addressing → PC + offset.
  • Indirect addressing adds a level of indirection: the register/address points to where the operand lives.

Book-Key Alerts

Because you said the exam questions are likely to come directly from this book, the quiz must follow the printed answer key. But some printed questions are internally inconsistent. This section separates exam-key memorization from correct conceptual understanding.

How the quiz handles this

Scoring follows the printed book answer. When a question conflicts with theory elsewhere in these same pages (or is clearly ambiguous), the explanation shows a red/orange Source inconsistency note. That way you can recognize the answer expected by the book without learning the concept incorrectly.

  • ALU Q4: the key chooses XOR as “not a logic operation,” but the theory on p.345 explicitly lists XOR as a logical operation.
  • ALU Q8-Q10: more than one listed truth statement is correct in some questions, while the key chooses only one.
  • Microinstruction Q11: the key says “Address field” is not part of the format, while the source's own 20-bit format explicitly contains AD (address field).
  • Instruction-format items: some MIPS bit-field choices do not match standard MIPS field sizes. The book answer is still preserved for exam-source fidelity.
  • Addressing-mode Q16: the wording does not line up cleanly with the source's own definition of immediate addressing.
Study strategy

For likely book-repeated MCQs, remember the printed key. For conceptual questions or engineering understanding, use the deep-review explanation and the inconsistency note.
